## What was built

- **ant-rai** is the OAuth 2.1 authorization server (Auth0 as identity provider, Liebre platform
  accounts) and hosts the sixteen read-only MCP endpoints under `/api/v1/mcp/*`, each guarded by a
  rai-issued `mcp_access` bearer token and rai's own access check (active Liebre account, business
  linked with `allowed` status). Liebre is called with rai's machine token plus the caller's
  `User-Id`.
- **luca-mcp** is the thin stdio client users install with `uvx --from git+https://github.com/liebre-ai/luca-mcp luca-mcp`:
  browser login against rai (PKCE, loopback callback), tokens in the OS keychain (file fallback),
  automatic refresh, 18 tools (login, logout, whoami + 16 data tools) that forward to rai.

## Addendum (2026-09-08 late): explicit Google login and staff access (ant-rai follow-up PR)

Anand's first real test hit the dev deployment (no `LUCA_RAI_URL`), whose login provider is still
Google because Auth0 is not configured there: the browser was already signed in to Google, so no
prompt appeared, and every tool then failed with "not a Liebre user". Closed in rai:

- `/oauth/authorize` sends `prompt=select_account` to Google, so the account is always chosen.
- Every Luca login goes through one policy (`endpoints/oauth/luca_policy.py`): a Liebre user must
  be active and acts as themselves; a Google login without a Liebre account gets read-only
  access to `MCP_STAFF_FIRM_IDS` (default `af-2` in dev, nothing elsewhere) under the
  `luca:staff` scope; anyone else is refused at login with the reason.

## Defects found and fixed on the way

1. **Every MCP call answered 500 for the firm admin.** rai's Python `BusinessStatus` enum lacked
   `import_failed`, a value present in the dev database; loading any such business through the
   ORM raised `LookupError`. Fixed by adding the value and by making the new DAO select plain
   columns (status cast to text) instead of whole entities, so a future unknown value cannot 500 a
   read.
2. **Refused logins left the terminal waiting.** A rejected login ended in a bare 403 page while
   the client listened for its callback until its timeout. rai now retires the pending
   authorization and redirects to the client's `redirect_uri` with `error`, `error_description`
   and `state`; the client shows the reason in about two seconds.
3. **Path-changing identifiers.** The client forwarded ids verbatim into the URL path; rai decodes
   `%2F` before routing, so `../../x` could address another route (harmless, but wrong). Ids are
   now validated locally (one segment, no slashes, whitespace, `?`, `#`, `%`, leading dot) and
   percent-encoded.
4. **Test harness stopped one hop early.** With rai on localhost its own `/oauth/callback`
   matched the "loopback callback" heuristic; the driver now stops only at the client's exact
   `redirect_uri`.
5. **rai `.gitignore` ignores any path component named `auth`** (`src/auth`, `tests/auth`); new
   files there need `git add -f`.
